### Q2. 知识内容来源

- **题域**：业务规则 / 数据契约
- **题干**：`knowledge/` 现有 94 知识点如何处理？内容由谁生产？
- **选项与利弊**：
  - A：保留现有内容作为资产
  - B：**开发者只提供「知识点标题」**，完整内容由 opencode 构建期检索理解后生成
  - C：开发者提供完整内容
- **开发者答复**：**B——只给标题，内容后续由 opencode 搜索/理解/解释生成**
- **采纳决策**：产品侧定义知识点 schema（含生成内容所需字段）；内容生产为**构建期**流程 + **预留可插拔内容源接口**（后续会话确认，见 Q5）。标题清单稍后提供，不阻断设计冻结。
- **关联落盘**：`overview_prd.md`、`FEAT-010 内容生产管线`、`_04_engineering_contract`（阶段 3）。

### Q3. MVP 范围

- **题域**：范围裁剪（Q1/Q2 必问）
- **题干**：原 v1 有 8 项能力（全景/图谱/时间线/路线/搜索/详情/本地档案/六端）。MVP 范围？
- **选项与利弊**：
  - A：**全量沿用 v1 八项**
  - B：只做图谱+详情+搜索，其余降 Phase 2
  - C：开发者逐项裁定
- **开发者答复**：**A（全量沿用 v1 八项能力）**
- **采纳决策**：Phase 1 (MVP) = 全量八项能力 + 双主题 + 交叉链接；Phase 2/3 承载账号云同步、应用内 AI 生成、算法趋势预测等非目标。
- **关联落盘**：`_02_phased_roadmap/rebuild_v2_phased_plan.md`、`overview_prd.md`。

### Q4. 视觉调性（宏观品味宪章）

- **题域**：视觉
- **题干**：重新设计的对标基调与玻璃尺度？
- **选项与利弊**：
  - A：深空星图工作台（暗色沉浸） / B：极简智库（亮色阅读优先） / C：数据仪表盘 / D：自定义
  - 玻璃尺度：局部毛玻璃（阅读区干净） / 纯扁平 / **全站玻璃拟态**
- **开发者答复**：**需支持日/夜双模式；UI 现代、符合近两年设计主流、含玻璃视觉；简洁；功能只在必要时展示；尽量以图标代替文字；图标须按项目调性重绘**。玻璃尺度选中 **全站玻璃拟态**。
- **采纳决策**：落盘 `DESIGN.md`（代号「极光玻璃 / Aurora Glass」）：全站玻璃外壳 + 阅读区高不透明玻璃保证 WCAG AA；日/夜一等公民；单一强调色；领域色仅功能点；自绘 SVG 图标族。DTO: 阅读优先护栏写入 §0.2 / §2 对比度护栏。
- **关联落盘**：`/DESIGN.md`、每个特性 PRD 的 `Inherits: /DESIGN.md`。
- > **后续裁定（见 Q9）**：本决策的**视觉代号与配色/字体实现（v5 极光玻璃）已被否决并重做**为 v6「琉璃 / Liuli Glass」；「日/夜双主题一等公民、阅读面保 WCAG AA、单一强调色、领域色仅功能点、自绘 SVG 图标族」等**原则保留**。

### Q5. 内容生成发生位置

- **题域**：对外契约 / 架构（高返工）
- **题干**：「根据标题生成完整内容」发生在构建期还是应用内运行时？
- **选项与利弊**：
  - A：构建期由 Agent 生成 JSON（应用仍纯本地静态，无运行时 AI）
  - B：应用内运行时实时生成（需后端 / API Key / 网络）
  - C：构建期生成 + 数据层预留可插拔内容源接口
- **开发者答复**：**C（构建期生成 + 预留接口）**
- **采纳决策**：MVP 无运行时 AI（保持「无后端」边界）；数据访问层定义 `KnowledgeSource` seam，构建期 JSON 为一个 Adapter，未来应用内生成/服务器拉取为第二 Adapter（阶段 1/2 立 ADR）。
- **关联落盘**：`FEAT-010`；阶段 1 ADR（待建）。

### Q6. 知识点字段集

- **题域**：数据契约 / 业务规则
- **题干**：生成内容覆盖哪些字段？是否允许链接跳转？
- **选项与利弊**：
  - A：沿用 v1 字段集 / B：在 v1 上扩充 / C：开发者自定
- **开发者答复**：**B——在 v1 基础上扩充（标签、难度、学习时长、媒体/公式），且「所有字段都要支持链接跳转」**

- **关联落盘**：`FEAT-007 详情与交叉链接`、`FEAT-010`。

### Q9. 阶段 0 冻结裁定与视觉重设计（v5 → v6）

- **题域**：验收 / 视觉 / 业务语义
- **开发者裁定**：
  - 视觉：**不通过，重新设计**
  - 业务语义：**需调整**
  - 阶段 0 冻结：**需修改后再冻结**
  - 知识点标题清单：**现在提供**（截至本记录仍待补交，不阻断设计冻结）
- **具体不满（视觉）**：字体与排版问题 / 配色问题 / 不够有辨识度 / 玻璃过满、不够高级 / **部分功能重复（例如「黑暗/白天模式切换」）** / 分页与功能按钮的边框显得很廉价。
- **重设计方向（开发者选项）**：**B —— 液态玻璃（高保真全站）**。
- **业务语义整改方式（开发者选项）**：**先自行优化，再提审**。
- **采纳决策**：
  - 视觉：v5「极光玻璃 / Aurora Glass」**退役**，重做为 v6「**琉璃 / Liuli Glass**」——① 四角色字体系统（衬线给 Display/Reading，无衬线给 Text，等宽给 Mono）；② **暖纸 × 深墨**冷暖对位 + **琉璃青**强调色；③ **三级液态玻璃**（blur 14/22/32）+ 光边(inset ring) + 折射光泽，**禁止 1px 实描边**；④ 星图签名 + 自绘「线·节点」图标族。
  - 业务语义：确立 **单一呈现铁律**（一能力一控件、一信息一主呈现）；**主题控件唯一**、**搜索入口唯一**、**领域趋势主呈现唯一**；演示壳(harness)与产品视觉隔离且不得重复产品控件。
- **关联落盘**：`/DESIGN.md`(v6)、`overview_prototype.html`(v6 视觉真理源)、`overview_prd.md`(v2.1.0 §6)、`FEAT-009`/`FEAT-001`/`FEAT-002`、`design_charter.md`、`freeze_signoff.md`、CR-rebuild_v2-03/04。
