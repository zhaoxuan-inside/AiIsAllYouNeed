## 1. 特性洞察与核心价值界定 (Framing & Discovery)

- **现状与摩擦**：手写 100 个知识点的完整解读工作量巨大且质量参差；纯众包/抓取又不可控。
- **用户雇佣任务 (JTBD)**：`When` 内容作者只想给出「有哪些知识点」，`I want to` 让系统据标题检索、理解并生成结构完整、可溯源的内容，`so I can` 低成本获得高质量知识库。
- **惊喜时刻**：只给标题，就能得到含定义/解读/论文/依赖/标签的完整词条，且彼此正确链接。
- **冷启动**：先给出 1～3 个标题跑通「标题→内容→界面」，验证管线后批量。

## 2. 交互形态比选与取舍 (Approaches & Trade-offs)

| 维度 | 方案 A（推荐） | 方案 B（弃用） | 取舍理由 |
|---|---|---|---|
| **生成时机** | 构建期（开发机）生成 JSON，应用仍纯本地静态 | 应用内运行时调用 LLM | 保持 v1「无后端」边界；运行时可离线；质量可控 |
| **接口形态** | 数据访问层定义 `KnowledgeSource` seam（构建期 JSON 为 Adapter） | 硬编码读取单一 JSON | 为 Phase 2「应用内生成/服务器拉取」预留，避免返工 |
| **质量把关** | 生成后必须过 schema + 引用完整性 + 依赖环校验，坏数据阻断打包 | 直接信任生成结果 | 防伪造/坏数据进产品 |

## 3. 详细字段与业务规则约束矩阵 (Specifications & Constraints)

| 阶段 | 输入 | 输出 | 规则/校验 |
|---|---|---|---|
| 1. 标题清单 | 开发者提供：标题 + 所属领域（可含别名/年份提示） | 结构化标题清单 | 标题唯一；领域须在领域定义内 |
| 2. 内容生成 | 标题清单 | 各知识点的完整字段内容 | 生成须**可溯源**（引用来源论文/资料）；禁止编造不存在的论文 DOI/链接 |
| 3. 契约校验 | 生成内容 | 校验通过 / 失败清单 | schema 合法；`id` 唯一；引用完整（领域/论文/依赖/相关必须存在）；**依赖环检测**；路线阶段与依赖顺序一致；WikiLink 无悬空（悬空降级告警） |
| 4. 编译打包 | 校验通过内容 | 可供应用消费的数据仓库 | 版本化 `schemaVersion`（前向兼容 Phase 2 服务器化） |

### 业务分支规则矩阵
1. **校验全通过**：打包进应用。
2. **校验失败**：阻断打包，输出精确失败清单（哪条/哪字段/为何），回到生成/人工修正。
3. **WikiLink 悬空**：告警并降级为纯文本，不阻断（除非超出阈值）。
4. **来源缺失**：标记为待补来源，超出阈值阻断。

## 4. 需求原子分解与行为驱动验收标准 (Requirements & Functional DoD)

### 4.1 原子需求

| 需求编号 | 简述 | 关联动作 | 验收证据 | 优先级 |
|---|---|---|---|---|
| `REQ-001` | 仅凭标题清单可生成完整内容 | 提供标题→生成 | 产出字段齐全且可溯源 | P0 |
| `REQ-002` | 生成内容须过 schema 与引用完整性校验 | 校验 | 非法用例被拦截并给出清单 | P0 |
| `REQ-003` | 依赖环被检测并阻断 | 构造环 | 构建失败且指出环路径 | P0 |
| `REQ-004` | 数据访问经 `KnowledgeSource` seam | 代码审查 | 应用不直接依赖具体 JSON 文件 | P0 |
| `REQ-005` | 数据带 `schemaVersion` | 校验 | 版本字段存在且被检查 | P1 |
| `REQ-006` | 坏数据不进入产品 | 全流程 | 任一步失败则打包被阻断 | P0 |

### 4.2 Gherkin

```gherkin
Feature: 知识内容生产管线

  Scenario: REQ-001 从标题到完整内容
    Given 开发者仅提供 3 个知识点标题及其领域
    When 运行内容生成与校验管线
    Then 生成 3 个结构完整、来源可溯的知识点并成功打包

  Scenario: REQ-002/003 坏数据被拦截
    Given 生成的某个知识点引用了不存在的依赖，或依赖关系形成环
    When 运行契约校验
    Then 打包被阻断，并输出被拦截的条目、字段与原因（含环路径）

  Scenario: REQ-004 内容源可插拔
    Given 应用通过 KnowledgeSource 接口读取数据
    When 审查数据访问代码
    Then 应用不直接绑定具体 JSON 文件路径（BuildTime JSON 仅为一个 Adapter）
```
