## 1. 特性洞察与核心价值界定 (Framing & Discovery)

- **现状与摩擦**：有依赖关系不等于有**学习顺序**；新手面对一堆概念不知道先学哪个。
- **用户雇佣任务 (JTBD)**：`When` 我想系统学习某领域，`I want to` 看到按「基础→进阶→前沿」分阶段、并按依赖顺序编号的路径，`so I can` 照着路径逐级深入。
- **惊喜时刻**：路线一眼可见「从哪里开始、下一站是什么、前沿在哪」。
- **冷启动**：由依赖拓扑 + 编辑分段生成；无分段时降级为单一「全部」阶段。

---

## 2. 交互形态比选与取舍 (Approaches & Trade-offs)

| 维度 | 方案 A（推荐） | 方案 B（弃用） | 取舍理由 |
|---|---|---|---|
| **阶段呈现** | 领域 Tab + 三阶段泳道（基础/进阶/前沿），节点带依赖序号 | 单列表 | 泳道让「阶段性」可视化，契合学习心智 |
| **顺序来源** | 依赖拓扑排序 + 编辑分段 | 仅编辑手排 | 拓扑保证依赖合法（构建期含环检测），编辑提供语义分段 |
| **趋势** | 页面末尾领域趋势卡（编辑标注） | 独立趋势页 | 收敛入口，减少页面跳转 |

---

## 3. 详细字段与业务规则约束矩阵 (Specifications & Constraints)

| 元素 | 规则 |
|---|---|
| 领域 Tab | 六领域（数据驱动）切换；默认第一领域 |
| 阶段泳道 | 基础 / 进阶 / 前沿；每阶段内按拓扑序编号；节点显示标题 + 序号 + 领域色点 |
| 依赖合法性 | 构建期校验：路线内前置依赖必须先于本节点出现；含环即拦截 |
| 领域趋势卡 | 领域级趋势文本（编辑标注）；可折叠 |
| 点击 | 节点进入知识点详情 |
| 空态 | 某领域无路线：展示引导进入图谱 |

## 4. 需求原子分解与行为驱动验收标准 (Requirements & Functional DoD)

### 4.1 原子需求

| 需求编号 | 简述 | 关联动作 | 验收证据 | 优先级 |
|---|---|---|---|---|
| `REQ-001` | 按领域展示三阶段路线 | 打开路线页/Tab | 阶段与拓扑序与数据一致 | P0 |
| `REQ-002` | 依赖顺序合法（前置在先） | 数据校验 | 同一路线内无「前置在后」；含环被构建期拦截 | P0 |
| `REQ-003` | 节点进入详情 | 点击节点 | 跳转对应详情 | P0 |
| `REQ-004` | 展示领域趋势 | 页面渲染 | 趋势文本与编辑标注一致 | P1 |

### 4.2 Gherkin

```gherkin
Feature: 领域发展路线

  Scenario: REQ-001/002 按阶段与依赖顺序学习
    Given 领域「机器学习基础」存在带依赖的知识点
    When 访客打开该领域路线
    Then 知识点按「基础→进阶→前沿」分组，且组内顺序满足依赖在前

  Scenario: REQ-003 进入知识点
    Given 路线已渲染
    When 访客点击某阶段节点
    Then 进入该知识点详情

  Scenario: REQ-004 领域趋势
    Given 该领域有编辑趋势标注
    When 访客滚动到路线末尾
    Then 展示领域趋势卡，内容与标注一致
```
